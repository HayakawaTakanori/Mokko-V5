# 日繰り表（資金繰り）アプリ 仕様書

作成日: 2026-07-02
対象: Cursor実装用（Claudeとの設計検討を経て確定した仕様）

---

## 1. 概要

日々の入出金を記録・管理する「日繰り表」アプリ。既存のExcelテンプレート（月日／内容／入金／出金／合計）をベースに、以下を自動化する。

- カード払いへの切替（出金日のスキップと引落日への付け替え）
- 借入金（長期・短期）の自動計上
- 固定費の自動計上
- 分割入出金の関連可視化

## 2. プラットフォーム／技術方針

- **対象環境**: Mac・iPad（両方で同一コードが動作すること）
- **形式**: 単一HTMLファイルによるPWA（Mokko/coin-calcと同じ方針。外部依存を避け、単一ファイルで完結させる）
  - iPadは「ホーム画面に追加」でアプリのように利用
  - Macはブラウザで直接開く、または同様にPWAとして追加
- **データ保存**: Dropboxに保存する単一JSONファイル（例: `shikinguri-data.json`）
  - Dropbox API（REST、PKCEによるOAuth）を使用し、SDK非依存で単一ファイル構成を維持
  - ローカルには直近データをキャッシュ（localStorage or IndexedDB）し、オンライン時にDropboxと同期
  - 同時編集は基本想定しない（単一ユーザー運用）。競合時は「最終更新が新しい方を優先＋警告表示」程度の簡易対応でよい
- **見た目**: Excelの表に近いシンプルなグリッドデザイン。装飾を避け、罫線・行区切りを明確に

### フィールド補足

| フィールド | 説明 |
|---|---|
| `entries[].type` | `income` または `expense` |
| `entries[].paymentMethod` | `cash` / `transfer`（口座振替）/ `card`（カード払い）/ `cardSettlement`（カード引落集計行） |
| `entries[].splitGroupId` | 分割入出金をまとめるグループID。同一グループのentryは合計表示・視覚的な関連付けを行う |
| `entries[].source` | `manual` / `fixedCost` / `loan` / `cardSettlement`。自動生成元の判別用 |
| `entries[].skipped` | true の場合、金額0円で元日付に表示される「付替済み」行 |
| `entries[].linkedEntryId(s)` | スキップ元⇔引落集計行の相互参照 |

## 4. 機能仕様

### 4.1 表示

- 表形式（月日／内容／入金／出金／合計）はExcelテンプレートに準拠
- 入出金の内訳（現金・当座預金・普通預金）は口座マスタに基づき動的表示（口座が増減しても対応できるようにする）
- **お金の動きがない日は非表示**（前項繰越行のみ起点として保持）
- 合計（残高）は「前日残高 ＋ 入金 － 出金」で自動計算し、行を追加・編集するたびに再計算
- 1日に複数件の入出金があってよい（同日で複数行）
- 表示期間: データ作成可能なのは最大1年先まで

### 4.2 手入力・編集

- 日付・金額・内容・口座・支払方法をあとから編集可能
- 編集した際は合計残高を再計算

### 4.3 分割入出金

- 1件の入金・出金を複数行に分割登録できる
- 同一 `splitGroupId` を持つ行は、表内で視覚的にグルーピング表示（枠線・背景色・インデント等）し、グループ合計金額を併記
- 分割はUI上で「この行を分割」操作から行、既存行を複数行に再構成する

### 4.4 カード払い切替

1. 出金行に対し「カード払いにする」を選択し、カード名（マスタから選択）と金額を指定
2. 元の出金日の行は残す。金額は0円とし、備考に「○○カードの引落日（YYYY-MM-DD）に付替」と表示（**ユーザー確定事項**: スキップしても行は消さず、金額0円で残す）
3. カードの締め日・引落日ルールに従い、対象期間内の利用分をカードごとに集計し、引落日に1行の合計出金として自動生成する
4. 集計行から内訳（対象の元行一覧）を辿れるようにする（`linkedEntryIds`）
5. カードマスタの締め日・引落日は「◯日締め、翌月◯日払い」のような月またぎ設定に対応（`paymentMonthOffset` で調整）
6. **引落日が土日祝の場合は翌営業日に繰り越す**。祝日判定用カレンダーは外部JSONから取り込む（土日は自動判定）

### 4.5 借入金

マスタに `type: "long"`（長期）／`"short"`（短期）を持たせる。

- **短期**: `dueDate` に指定した期日に、`balance` 全額を一括出金として自動計上
- **長期**: `paymentDay` に毎月 `monthlyPayment` 分の出金を自動生成。**残高がゼロになるまで生成を継続**（回数や完済予定日はマスタに持たせず、都度残高から自動判定）
  - 生成のたびに `balance` を減算し、0円以下になった時点で以降の生成を停止

### 4.6 固定費

マスタ項目: 名称・金額・支払期日（`dueDay`）・口座・支払方法（現金／口座振替／カード払い）・開始日／終了日（任意）・有効フラグ

- 有効な固定費は、表示期間（最大1年先まで）内の該当日に自動で出金行を生成
- `paymentMethod: "card"` の固定費は、4.4のカード払いロジックと同様に締め日・引落日に応じて自動的に付け替え処理される
- `startDate`/`endDate` がある場合はその範囲内のみ生成、`active: false` の固定費は生成しない

## 5. 計算ロジックまとめ

1. マスタ（固定費・借入金）から、表示期間（今日〜1年後）分の `entries` を都度生成（保存はしてもよいが、マスタ変更時に再生成できる設計が望ましい）
2. `paymentMethod: "card"` のentryはカード引落ロジックで元日付を0円化し、引落日に集計行を生成（引落日が土日祝の場合は翌営業日）
3. 日付順にソートし、口座横断の合計残高を `前日残高 + 入金 − 出金` で通し計算
4. お金の動きがゼロの日（生成されたentryが存在しない日）は表示から除外

## 6. 確認・未確定事項（実装時に要相談）

- 口座ごとの内訳表示（現金／当座預金／普通預金）を、口座マスタの増減に応じて動的な列にするか、当初の3列固定にするかは要確認
- Dropbox同期の競合解決（複数端末からほぼ同時編集した場合の挙動）→ **アイデア募集中**（現状は暫定実装のみ。下記参照）
- ~~カード締め日・引落日が土日祝と重なった場合の営業日調整要否~~ → **確定**: 翌営業日に繰越。祝日は外部JSON取込
- 固定費マスタの追加候補項目（勘定科目・内容欄、支払方法別処理）は前段の検討で提案したもの → **確定**: 勘定科目は不要。名称・金額・支払期日・口座・支払方法で十分

### 営業日カレンダー（外部JSON）

祝日一覧を外部から取り込み、カード引落日の営業日調整に使用する。

```json
{
  "name": "2026年祝日",
  "holidays": ["2026-01-01", "2026-01-12", "2026-02-11"]
}
```

- `holidays`: `YYYY-MM-DD` 形式の祝日配列（配列のみのJSONも可）
- 土日はアプリ側で自動判定
- データは `calendar` フィールドに保存され、Dropbox同期の対象に含まれる
- サンプル: `docs/sample-holidays-2026.json`
